# archive — первая реализация, законсервирована

Здесь лежит рабочая версия crescent, которая делала своё дело **в обход
Codex**: читала rollout-файлы напрямую и запускала `codex exec resume` вторым
клиентом поверх того же хранилища сессий.

Она работает. Она собирается, тесты проходят, CI зелёный, и запустить её можно:

```sh
go run ./archive/cmd/crescent -run
```

Убрана она не потому, что плоха, а потому, что решала не ту задачу.

## Почему законсервировано

Пока запущено десктопное приложение ChatGPT, Codex отказывается возобновлять
сессии, которыми оно управляет: `thread-store conflict: thread … already has an
active writer`. Это не препятствие, которое надо обойти, — это корректная
защита от двух писателей в один тред. Обходя её, мы и были тем вторым
писателем.

При этом у Codex есть штатный интерфейс ровно для того, что нужно, — JSON-RPC
app-server:

| нужно                     | метод                                              |
|---------------------------|----------------------------------------------------|
| есть ли доступные токены  | `account/rateLimits/read`                          |
| узнать о сбросе лимита    | `account/rateLimits/updated` (уведомление)         |
| потратить сохранённый сброс | `account/rateLimitResetCredit/consume`           |
| список целей и имён чатов | `thread/list`, `thread/goal/get`, `thread/read`    |
| запустить цель            | `thread/resume`, `turn/start`, `thread/goal/set`   |
| очередь тредов            | `thread/queue/add`, `thread/queue/start`, …        |

Транспорты: `stdio://`, `unix://PATH`, `ws://IP:PORT`.
Rendezvous-сокет отдельно запущенного сервера —
`$CODEX_HOME/app-server-control/app-server-control.sock`.

То есть весь слой разбора rollout-ов заменяется несколькими запросами.

## Что здесь всё-таки ценно

Разбор был написан терпимым к схеме и проверен на реальном каталоге из 338
сессий. Если протокол окажется недоступен — например, приложение не отдаёт
сокет, а поднимать свой app-server нельзя, — этот код остаётся запасным путём
и включается обратно перемещением каталогов.

Отдельно стоит сохранить наблюдения, добытые дорого:

* цель пишется в rollout в момент постановки, поэтому в трёхсуточной сессии
  лежит в середине файла — читать края бесполезно;
* имена чатов в rollout-ах отсутствуют вовсе, они в `session_index.jsonl`
  под ключом `thread_name`;
* снимок лимитов пишется в сессию при упирании в лимит; окон два — скользящее
  пятичасовое и недельное;
* сообщение о лимите приходит и как событие `error`, и как `turn.failed`,
  текст вида `You've hit your usage limit. … or try again at 10:33 PM.`;
* отказ из-за занятого треда приходит на stderr, а не в поток `--json`;
* `cwd` бывает `file://`-ссылкой, percent-закодированной, а на Windows с
  ведущим слэшем от URL.

Всё это проверено на живых данных и записано в тестах рядом.

## Что не отсюда

`goWidgets` — отдельный репозиторий и к консервации отношения не имеет. Окно,
иконка в трее, две платформы без cgo — это остаётся и используется дальше.
